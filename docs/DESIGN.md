# 关键设计与适用范围

EGIP 将事实纠错视为受尝试预算约束的决策问题：给定文本与证据，先决定干预哪里，再生成与选择修订。该思路可作为知识问答或内容核验流程中的研究组件；本仓库尚未提供业务服务或生产部署。

## 为什么单独设计规划阶段

相关性回答“片段是否与文本主题有关”，干预优先级回答“结合证据，这个片段是否值得尝试修改”。二者承担不同任务。项目通过扰动差异构建候选级监督，并学习证据条件下的优先级，再与相关性、多样性共同排序。

候选保留多个长度与重叠范围。局部错误需要多少上下文才能被纠正并不固定；提前禁止重叠可能排除有效的修改范围。多样性用于减少相似干预，但不会保证每次生成的修订都不同。

## 如何定义和使用预算

`K` 是每条输入的纠错尝试预算，主要设置为 2。选中的每个候选分别遮盖原文，并送入同一个纠错器。一次尝试即使没有改变文本或产生重复输出，仍消耗预算。

各次尝试独立，避免前一次修订改变后一次的输入。未修改原文作为额外备选，不计入生成尝试。最终选择考虑纠错置信度及修订特征；保留原文是一种备选机制，不等于已验证的安全保证。

`K` 不等同于端到端费用或延迟。完整计算还包含候选评分、编码、验证与选择；业务中应同时测量实际推理时间、token 用量和错误类型。

## 如何判断方法是否有效

研究使用 FECDATA 与 SciFact-FEC 的给定证据纠错设置，以 SARI 和 Exact Correction 衡量输出。比较规划策略时保持候选空间与共享纠错后端一致，并分析预算变化，帮助区分规划带来的变化与生成模型带来的变化。

开发数据用于拟合与参数选择，测试参考仅用于输出评估。评估脚本检查预测与数据的对应关系及数量。仓库不分发完整实验结果；相关研究结果由论文报告。这里也未将研究指标换算成业务收益。

## 流程示例与完整方法的区别

`examples/planning_walkthrough.py` 使用虚构输入，调用真实候选构造、排序和遮盖函数，但人工设置优先级并使用 TF-IDF 向量。它用于解释规划逻辑。

完整方法通过训练的优先级模型读取文本与证据，使用语义编码器计算相关性与多样性，并接入共享纠错后端及修订选择器。完整运行命令见 [训练、推理与评估](REPRODUCIBILITY.md)。示例不替代模型验证。

## 接入真实业务时需要解决什么

本方法假定证据已提供，效果受证据覆盖与可信度影响。目前研究数据不覆盖所有语言、行业文档或长篇多事实输入。模型可能生成错误修订，选择器也可能选错。

面向具体业务，需要先定义输入单元、证据来源与验收标准，再用业务样本评估错误类型、实际延迟及成本。检索接入、模型服务、监控和人工复核策略尚未在本项目中实现。
